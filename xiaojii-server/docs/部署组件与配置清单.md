# 校集 · 部署组件与配置清单（Docker / 云服务器）

> 服务器：阿里云轻量 `8.134.171.71`（2 vCPU / 1600MB 内存 / 40G 磁盘，Ubuntu 22.04，Docker 29.9.1 + 1Panel）
> 现状采集时间：2026-10-18 13:10（以下端口、资源数字均为服务器实测值）

## 一、现状盘点（决定方案的三条硬约束）

| 实测项 | 结果 | 对部署的影响 |
|---|---|---|
| 内存 | 总 1608MB，已用 855MB，可用 579MB，Swap 2GB | **不能给校集开大堆内存**，JVM 必须限到 256MB |
| 端口 8080 | 已被 `blog-server`（systemd 托管的 jar，非容器）占用 | 校集**必须换端口**，方案取 `8081` |
| 端口 3307 / 6379 | MySQL8.0 与 Redis7 容器，均只绑 `127.0.0.1` | 校集容器**不能**用 `127.0.0.1` 连它们，必须走 Docker 网络或 host-gateway |
| Nginx | 已接管 80/443，`sxz-blog.xyz` 的 `/api/` 已指向 blog 后端 | 校集的 `/api` **不能**复用同一域名路径，必须独立子域 |
| 证书 | `/etc/letsencrypt/live/` 下已有 `sxz-blog.xyz`、`xing.sxz-blog.xyz` | 新子域需单独签发（certbot 一条命令） |
| 磁盘 | 40G，已用 11G，剩 27G | 上传目录放本地磁盘完全够用 |
| Docker 日志 | daemon.json 已配 `max-size 10m / max-file 3` | 无需额外处理日志轮转 |
| MySQL 参数 | buffer_pool 64MB，max_connections 50，实测占用 131MB/512MB 限额 | 容量够校集用，不必再开实例 |
| Redis 参数 | 实测 3.5MB/192MB 限额，`maxmemory 96mb`，**`allkeys-lru`**，`RestartPolicy=no` | ⚠️ 两个必须处理的问题，见 §六 |

## 三、组件清单（含依赖与部署顺序）

| # | 组件 | 形态 | 用途 | 依赖 | 端口 | 资源 |
|---|---|---|---|---|---|---|
| 0 | 目录与网络 | 宿主资源 | `/opt/xiaojii/{uploads,logs}` + `xiaojii-net` | Docker | — | 磁盘 <1G 起步 |
| 1 | **MySQL8.0** | 容器（**已存在**） | 业务库 `xiaojii`（22 表） | 磁盘卷 `/opt/docker/mysql-data` | 127.0.0.1:3307→3306 | 限额 512MB，实测 131MB |
| 2 | **Redis7** | 容器（**已存在**） | 登录态白名单、限流、幂等 | — | 127.0.0.1:6379 | 限额 192MB，实测 3.5MB |
| 3 | 库表初始化 | 一次性任务 | 执行 `schema.sql` / `init_data.sql` | 1 | — | — |
| 4 | **xiaojii-server** | 容器（★新增） | 全部业务 API（`/api/app/**`、`/api/admin/**`） | 1、2、3 | 127.0.0.1:8081→8081 | 限额 448MB，JVM `-Xmx256m` |
| 5 | **Nginx 站点** | 宿主进程（**已存在**） | HTTPS 终止、反代 `/api` 到 8081 | 4 | 443 | 常驻约 10MB |
| 6 | 备份任务 | 宿主 cron | 每日 dump `xiaojii` | 1 | — | 压缩后 <5MB/天 |
| 7 | 管理端 Web（后续） | Nginx 静态托管 | 审核/仲裁后台页面 | 4 | 443 | 无 |

**部署顺序的理由**：先有存储（MySQL/Redis），再有表结构，再有应用，最后挂反向代理——反代一旦生效，后端必须已经能响应，否则小程序会拿到 502。

### 2. Redis7（已运行，有两处必须改）

| 项 | 值 / 做法 |
|---|---|
| 连接方式 | 容器内 `Redis7:6379`；宿主 `127.0.0.1:6379` |
| 密码 | 当前在 `docker run` 的 Command 里（`docker inspect` 明文可见）→ 改挂载 `redis.conf`，`requirepass` 写文件 |

### 3. xiaojii-server（唯一需要新建的容器）

**镜像**：本地 `./mvnw package` 出 49MB jar，连同 Dockerfile 上传后 `docker build`，避免在 2G 机器上跑 Maven。

```dockerfile
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
RUN addgroup -S app && adduser -S app -G app
COPY xiaojii-server-1.0.0.jar app.jar
RUN mkdir -p /app/uploads /app/logs && chown -R app:app /app
USER app
ENV TZ=Asia/Shanghai \
    JAVA_OPTS="-Xms128m -Xmx256m -XX:MaxMetaspaceSize=128m -XX:+UseSerialGC"
EXPOSE 8081
ENTRYPOINT ["sh","-c","exec java $JAVA_OPTS -Duser.timezone=Asia/Shanghai -jar /app/app.jar"]
```

**运行参数**

| 项 | 值 | 说明 |
|---|---|---|
| 端口 | `-p 127.0.0.1:8081:8081` | 只绑回环，公网不可直连，统一走 Nginx |
| 网络 | `--network xiaojii-net` | 用容器名解析 MySQL/Redis |
| 内存 | `--memory 448m --memory-swap 640m --cpus 1.0` | JVM 256m + Metaspace 128m + 直接内存/线程栈 |
| 重启 | `--restart unless-stopped` | 与 MySQL 对齐 |
| 数据卷 | `/opt/xiaojii/uploads:/app/uploads` | 图片，**必须持久化**，否则重建容器丢图 |
| 日志 | 不挂卷，走 stdout（daemon 已配 10m×3 轮转） | |
| 时区 | `-e TZ=Asia/Shanghai` | 业务时间依赖 |

**环境变量（全部必填/按需）**

| 变量 | 示例 | 说明 |
|---|---|---|
| `XIAOJII_PORT` | `8081` | 应用端口 |
| `DB_URL` | `jdbc:mysql://MySQL8.0:3306/xiaojii?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true&rewriteBatchedStatements=true` | 容器名解析 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `***`（密码见 `E:\WorkBuddy输出\凭据\sxz-blog-服务器凭据.md`【唯一权威】章节） | 2026-10-18 15:00 起 root 是唯一账号；⚠️ `xiaojii_app`、`app` 均已 DROP，照旧文档填会直接 1045。生产上线前应新建最小权限账号替换 root |

### 4. Nginx（复用现有实例，新增一个 server 块）

⚠️ **不能复用 `sxz-blog.xyz/api/`**：那条 location 已经指向 blog 后端。必须用子域。

```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name xj.sxz-blog.xyz;

    ssl_certificate     /etc/letsencrypt/live/xj.sxz-blog.xyz/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/xj.sxz-blog.xyz/privkey.pem;

    client_max_body_size 8m;          # 与 spring multipart 5MB 匹配并留余量

    location /api/ {
        proxy_pass         http://127.0.0.1:8081/api/;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}
```

图片无需单独 location —— `/api/files/**` 由 Spring 自己提供。

### 5. 备份（新增一条 cron，与 blog 的备份互不影响）

```bash
# /etc/cron.d/xiaojii_db_backup   每日 03:40（避开 blog 的 03:30）
40 3 * * * root docker exec MySQL8.0 mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --default-character-set=utf8mb4 xiaojii \
  | gzip > /opt/backup/xiaojii/xiaojii_$(date +\%F).sql.gz
```
保留 7 份，另建议每周把 `/opt/xiaojii/uploads` 打一次 tar（图片丢了没法从库里恢复）。

## 五、资源预算（2G 内存能否扛住）

| 组件 | 实测/预估 | 限额 |
|---|---|---|
| 系统 + Nginx + 1Panel | ~250MB | — |
| blog-server（JVM Xmx320） | ~350MB | systemd |
| blog-portal（Next.js） | ~150MB | systemd |
| MySQL8.0 | 131MB | 512MB |
| Redis7 | 3.5MB | 192MB |
| **xiaojii-server（新增）** | **~300MB**（Xmx256） | 448MB |
| 合计 | **~1180MB / 1608MB** | 余量 ~400MB + 2G Swap |

结论：**能跑，但没有余量**。日常够用；一旦小程序做并发压测或有爬虫，JVM 会和 blog 抢内存触发 swap，表现为接口偶发 1-2 秒卡顿。若这个项目要长期在线，建议升到 **2C4G**（内存翻倍最划算），或在压测期临时停 `blog-portal`。

## 六、必须提前决策的 5 件事

1. **Redis 共用还是独立**：共用现有实例会与 `allkeys-lru` 冲突（登录态被淘汰）。推荐 **给校集单开一个 Redis 实例**（`--memory 128m --maxmemory-policy noeviction`），成本仅多 64MB 内存，换来登录态稳定。
2. **域名**：建议 `xj.sxz-blog.xyz`（主域已备案，子域不需单独备案）。需要加一条 A 记录并签证书。
3. **小程序 AppID / AppSecret**：没有它只能 dev-login，上线前必须填。
4. **管理员初始密码**：`admin/admin123` 必须改（`PasswordUtil` 生成新哈希后 UPDATE）。
5. **是否保留 1Panel 公网访问**：`10086` 对公网开放且密码 8 位，建议改成只允许固定 IP 或走 SSH 隧道。
